# Operation No Pants Animation Studio 🎬

A free, open-source 2D animation pipeline using Python, Pillow, FFmpeg, and GitHub Actions. No paid APIs.

## Phase 1 — original fish (preserved)
`python animate.py` generates `output/fish.gif` and `output/fish.mp4`. Its original source remains untouched.

## Phase 2 — configuration-driven scenes (preserved)
`python studio.py --config scenes.json` generates fish, ball, and star animations with configurable backgrounds, movement, duration, size, and frame rate. Its source and scenes remain untouched.

## Phase 3 — layered characters and multi-shot storyboards
`python characters.py --config storyboard.json` creates GIF/MP4 short stories from a JSON storyboard. Characters use separately composed background, limbs, body, head/hair, face and caption layers. Supported actor `color`: lavender, coral, mint; `pose`: wave, idle, jump; `expression`: happy, surprised, sleepy. Supported backgrounds: studio, garden, stage.

Each story contains ordered `shots`, with independent `duration` (0.5–10 seconds), `background`, `actor` and optional `caption` (up to 90 characters, must fit frame). Story `fps` 1–24, `size` 320×240 through 1280×720, up to 12 shots. The included `hello_lavender` example demonstrates three sequential shots and expressions.

Run locally after installing Python, FFmpeg and `pip install -r requirements.txt`. On GitHub, open **Actions → Render free animation → Run workflow**. The workflow renders all three phases and uploads one ZIP artifact.

## Scope and limitations
These are simple procedurally drawn cartoon characters, not generative AI, imported sprite rigs, lip-sync, sound, or a graphical editor. The JSON file is the scene editor. For now, captions are single-line, and animated GIF timing may vary slightly from MP4 due to centisecond timing.

## Roadmap — future work (not implemented yet)
- **Phase 4:** richer layered sprite/character assets, pose transitions, caption wrapping, and scene editing.
- **Phase 5: open-source audio integration:** optional locally generated character voices (evaluate Piper TTS voice/model licenses and runtime requirements), user-recorded dialogue, original or appropriately licensed music and sound effects, and FFmpeg mixing with timeline synchronization, volume balancing, and MP4 audio muxing.
- Preserve silent GIF exports (GIF does not support audio). MP4 will carry synchronized sound once Phase 5 is implemented.
- No paid services, no assumed commercial-use rights, and no heavyweight speech model installation until benchmarked.

## Phase 4 — reusable characters, expressive poses and wrapped dialogue
Run `python phase4.py --config phase4.json` to render `output/phase4_story/phase4_story.gif` and `.mp4`. Named character profiles in `phase4.json` control outfit color (lavender, coral, mint, blue), hair (dark, brown, gold) and horizontal position. Each shot chooses a character, background (garden, studio, night), pose (idle, wave, jump, walk), expression (happy, surprised, sad, sleepy, neutral), duration, caption, and optional `transition: fade` (otherwise cut). Eased jumping and crossfade transitions improve movement; captions automatically wrap to up to three lines.

The Phase 4 workflow also renders the original fish and every Phase 2–3 example. This is a simple procedural 2D animation engine; it does not yet provide sprite import, audio, a GUI, or lip synchronization. Phase 5 voice/music/sound effects/FFmpeg mixing remains **planned only**.

## Phase 4.1 — GIF timing and caption polish
Phase 4's GIF export now distributes 10-millisecond GIF delay quantization across frames instead of rounding every frame to the same delay. For the default 12 fps, 72 frames total exactly 6.00 seconds. Scene crossfades now blend **caption-free scene frames** and render only the incoming shot's caption afterward, avoiding overlapping dialogue. The Phase 1–3 engines are unchanged. GIF players may still vary in their interpretation of frame delays. Phase 5 audio remains future work.

## Phase 5 — offline audio MVP (WAV to synchronized MP4)
`audio.py` takes an existing silent MP4 and one or more **user-provided, uncompressed PCM WAV** recordings, with per-track start time in seconds and volume, and creates a separate iPhone-friendly H.264/AAC MP4. It never alters the original MP4 or silent GIF. Edit `audio.json` with your own local WAV file paths; **only use music/sound effects you created or have rights to use**. Tracks beyond the video duration are trimmed; gaps are silent. No voice cloning, TTS, paid APIs, or music downloads are part of this MVP.

Usage after rendering Phase 4: `python audio.py --config audio.json`. For CI only, `python audio.py --make-demo-tone assets/audio/demo_tone.wav` creates an original, short 440 Hz test beep, **not a voice performance**. Replace it with a recording to hear real speech. GitHub Actions runs the synthetic test and uploads the audio MP4 alongside the preserved 12 silent exports. FFmpeg is provided by the open-source `imageio-ffmpeg` wheel in the workflow. This is the first step toward the preserved roadmap of user voices, licensed SFX/music, optional vetted open-source TTS, and more advanced timeline mixing.

**Playback note:** The existing Phase 4.1 MP4 was validated as H.264 and converted to a compatible baseline variant; whether the ChatGPT iOS app opens a particular sandbox link still depends on the client. GitHub Actions artifacts provide a second download route.

## Anime-inspired layered visual proof of concept
Run `python anime_layers.py` to generate `output/anime_layers/anime_layers.mp4` and `.gif` using original Pillow-drawn artwork: independent gradient sky/stars, distant illuminated city, illustrated character, foreground drifting petals, blurred glow, cinematic letterboxing and camera parallax. This is a 4-second 640x360 12fps demonstration of **layered compositing and cinematic motion**, not production-quality frame-by-frame anime, lip sync, or imported AI art. It preserves the Phase 1–5 scripts and their outputs. All artwork is created in code, with no paid APIs or outside assets.

## Character Rig 2.0 — independent face and hair animation
Run `python rig2.py --config rig2.json`. The versioned JSON defines character palette, performance duration, title, and a **future** transparent-PNG layer contract. The renderer procedurally draws separate body, back-hair, head, eyes, eyebrows, three mouth poses and front-hair elements, with independently timed blinks, brow movement, fringe sway, nod and body sway, over the preserved parallax city. Outputs a 5-second H.264 Baseline MP4 and silent GIF under `output/rig2_performance/`. This is **not** yet a PNG importer, head-turn rig, real lip sync, or hand-animated anime. `future_assets` is descriptive metadata only; importing Krita/OpenToonz exports is the next step. Existing Phase 1–5 tools and their audio files are unchanged.

## Character Rig 2.1 — real transparent PNG import
Run `python rig21.py --make-demo` to create an **original 10-layer transparent RGBA PNG asset pack on disk** at `assets/rig21/`, plus a versioned `manifest.json`. Run `python rig21.py --manifest assets/rig21/manifest.json` to **re-open each PNG file from disk**, validate its size/alpha/path, composite it by named layer and manifest anchor/scale, and animate blink variants, three mouth variants, independently swaying front/back hair, eyebrows, head and body. Outputs `output/rig21/rig21.mp4` and silent `rig21.gif`, 5 seconds at 640x360 12fps. The GitHub workflow generates and imports the actual PNGs, proving the importer is not merely a placeholder. To replace artwork, export each layer from Krita or OpenToonz as a transparent **360x380 RGBA PNG** with the same layer name and canvas alignment, then edit manifest anchors/scales as necessary. Manifest format_version=1, layer entries: `{"file":"head.png","anchor":[0,0],"scale":1}`. Supported scale .8–1.2; fixed compositing order. Limitations: no PSD/ORA import, free-form skeletal deformation, head-turn views, true speech-driven lip-sync, or full HD production pipeline yet. The test pack is generated during CI, not committed as binary art; bring your own art for professional-quality visuals. Prior Phase 1–5 and Rig 2.0 engines remain unchanged.

## Love in the Cloud visual-quality experiment (not production anime)
Run `python visual_quality.py`. It generates original before/after transparent RGBA PNG packs, **re-imports both via the verified Rig 2.1 loader**, and checks that five relevant layer files differ. The new pack adds subtle facial contours, eye details, hair highlights, and clothing accents without modifying existing rig logic. GitHub Actions renders a genuine side-by-side `output/visual_quality/before_after.png` plus a 4-second animated MP4/GIF of the revised art. This is a deliberately small, objective pipeline test; it is **not** professional anime, a Darcy-approved character design, a complete character sheet, or a trained generative model. Production recommendation: paint original character turnarounds and facial variants in Krita, export matching transparent 360x380 RGBA PNG layers, and import via Rig 2.1. Krita's GPL license permits commercial artwork, which remains the artist's property; confirm licenses of any third-party brushes/assets. OpenToonz is a possible later animation editor; it is not required in CI. Remaining: character-design approval, higher-res rig, head-turn/gesture art, lip-sync, dialogue and 15-second two-character scene.

## Motion Reference Sprint 1: honest marker-video MVP
Run `python motion_sprint1.py` with FFmpeg and Pillow. The program creates a **project-owned synthetic reference video** (FFV1 lossless MKV), decodes that real video into frames with FFmpeg, detects three red markers using connected components, exports `output/motion_sprint1/motion.json`, measures tracking error against source coordinates, and renders a separate animated character from **detected coordinates**, exporting GIF and MP4. No third-party footage is downloaded or used; rights/provenance: all original geometric artwork and synthetic reference movement generated in this repository, no external performers, no third-party footage license. This tests the video-to-data-to-animation interfaces, **not** human pose inference, MediaPipe, facial acting, full-body motion capture, anime-level artwork, or production retargeting. MediaPipe is a candidate for next sprint and requires an independently licensed pose model and video test. Public-domain archive candidates need per-file rights verification; no archival footage has been accepted into our asset library. Cost: $0 additional software/license/API fees; runner time, labor and electricity are not free. Next roadmap gate: test a rights-cleared real human gesture with MediaPipe and compare landmark stability; then design deformable 2D arm artwork for rig retargeting. All older animation/audio pipeline steps remain intact.

## Motion Sprint 2 — real human MediaPipe experiment
`motion_sprint2.py` uses Wikimedia Commons `HandWaveExample.webm` (creator NMu11er; **CC BY-SA 4.0**, https://commons.wikimedia.org/wiki/File:HandWaveExample.webm ; license https://creativecommons.org/licenses/by-sa/4.0/). This is *freely licensed*, **not public domain**. Credit the author, link license, indicate changes; assess ShareAlike obligations for any distributed adaptations. The script downloads the source and Google's MediaPipe pose-landmarker-lite model during CI; decodes video to 8 fps 480px, detects human pose landmarks, records left/right shoulder, elbow and wrist positions/visibility, calculates frame coverage and frame-to-frame wrist displacement, and retargets one arm to a new original cartoon figure. It fails rather than falling back to synthetic coordinates if source/model download or pose detection fails. Original source is a **group** of people, so the detector may select different subjects; pose identity tracking and movement accuracy against annotated ground truth are **not verified**. Mean wrist displacement is a stability proxy conflating actual movement and tracking jitter, not true error. `output/motion_sprint2/pose.json` contains measurements, GIF/MP4 contain the original character animation. MediaPipe code is Apache-2.0, but model redistribution terms must be checked separately; model downloaded for runtime use, not redistributed in GitHub artifacts. Additional paid license/API cost $0; network/runner compute and human labor are nonzero. **Quality gate:** Do not claim this is production anime or stable single-person tracking. Next: rights-cleared single-person footage, manual landmark ground-truth samples, subject identity checks, smoothing and deformable arm art. Existing Sprint 1 and earlier renders preserved.

## Motion Sprint 2.1 — constrained 2D arm (quality gate)
`motion_sprint21.py` reads actual Sprint 2 MediaPipe landmarks and computes two arm segment orientations, smooths their circular angles, then retargets onto an **unchanging shoulder anchor** with **62px upper arm and 59px forearm**. It exports an actual GIF/MP4, 3-row before/after image, and metrics JSON. CI asserts maximal segment-length error <1e-8 pixels; reports pose coverage and raw/smoothed angular step. Angular step is **not** validated tracking jitter; it includes genuine motion. No additional model or paid service. Source remains Wikimedia Commons `HandWaveExample.webm`, attributed to NMu11er, CC BY-SA 4.0; the **single-person source requirement is still open** because that source contains multiple people. We do **not** claim verified subject identity or natural anime acting. Two-attempt breaker: if a single-person footage replacement cannot be verified promptly, retain the rights-documented group benchmark, mark identity blocked, and do not claim success on it. Next gate: license-verified one-person performance, person-identity consistency, manually checked keyframe joint landmarks, real artistic character rig.

## Motion Sprint 2.2 — layered character arm (identity BLOCKED)

It tests bone-length error, reports pose coverage, joint-limit clamp and wrist continuity, and exports GIF/MP4 and a 3-keyframe before/after against Sprint 2.1.
